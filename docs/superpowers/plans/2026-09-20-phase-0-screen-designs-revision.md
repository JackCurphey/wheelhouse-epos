# Phase 0 — Atlas Revision Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply Jack's 13 screen-review notes to the journey atlas so it becomes the build target the later phases implement, rather than a document the build contradicts.

**Architecture:** The atlas is generated, not hand-written. `screens.js` and `branches.js` declare every screen through one `add(id, group, title, role, body, note, next, pack, branches)` call; `package.py` inlines them into a single offline HTML file; `check-static.mjs` loads that file in jsdom, asserts structure and behaviour, and regenerates `screen-index.json` and `verification.json`. Every task in this plan therefore edits a declaration, re-packages, and re-checks. A new `check-notes.mjs` holds one assertion per note, so "the revision is complete" is a command that passes rather than an opinion.

**Tech Stack:** Node 20+ (ESM, `node:assert/strict`), jsdom (resolved from `prototype/node_modules`, not installed at the repo root), Python 3 stdlib only for `package.py`.

**Spec:** [`docs/superpowers/specs/2026-09-20-release-1-screen-build-design.md`](../specs/2026-09-20-release-1-screen-build-design.md)

**Source of the notes:** [`docs/reviews/2026-09-17-release-1-screen-review-jack.md`](../../reviews/2026-09-17-release-1-screen-review-jack.md) — 84 of 84 screens reviewed, 71 approved as shown, 13 carrying notes.

## Global Constraints

- **No new dependencies.** `package.py` is Python stdlib only. The atlas checks resolve jsdom from `../../../prototype/node_modules/jsdom/lib/api.js`; do not add jsdom to the repo root `package.json`. The repo root has exactly one runtime dependency, `pg`.
- **Never edit `Wheelhouse-Release-1-Journey-Atlas.html` by hand.** It is generated. Edit `screens.js` / `branches.js` / `screen.css` / `atlas.js` / `template.html`, then run `python3 docs/design/release-1-journey/package.py`.
- **Fixture contract is fixed:** Maya Patel, green Trek Domane AL 3, job `WH-1042`, North Street Cycles, base service £65, brake pads £28, fitting £18, optional cable £12, canonical agreed total **£111.00** with the cable declined. `check-static.mjs` asserts £111.00, £123.00 and £77.00 exactly. Do not change these numbers.
- **British English** throughout user-facing copy. Spell out acronyms on first use.
- **No fabricated data.** Screens show only fields with a real source. The specimen QR/barcode resolves to the reserved example URL `https://wheelhouse.example/staff/jobs/WH-1042`, which is not a live route.
- **Every form control needs a label** (`<label>` wrapper or `aria-label`). `check-static.mjs` fails the build otherwise.
- **Every screen needs an `<h1>`**, a resolvable `next`, and resolvable `branches` and `parent.jump('...')` targets.
- **Decisions already made — do not re-open.** Tag carries a Code 128 barcode only, with the layout and resolver kept able to take a QR later. "Appointment only" is a third booking mode where walk-ins go to an untimed shared queue. Deposits are out of Release 1 entirely. The mechanic job page is two columns in landscape (agreed work left, work being done right), collapsing to one scrolling column in portrait. Individual services are grouped by shop-defined category on the second page.

- [ ] **Step 1: Write the failing test**

```js
// Asserts Jack's 17 September review notes have been applied to the atlas.
// Run after: python3 package.py && node check-static.mjs
import { readFile } from 'node:fs/promises';
import assert from 'node:assert/strict';

const url = new URL('./', import.meta.url), path = n => new URL(n, url);
const index = JSON.parse(await readFile(path('screen-index.json'), 'utf8'));
const source = (await readFile(path('screens.js'), 'utf8'))
  + (await readFile(path('branches.js'), 'utf8'));

const byId = id => {
  const screen = index.find(s => s.id === id);
  assert.ok(screen, `No screen with id "${id}"`);
  return screen;
};

// The add(...) call for one screen: from add('<id>' up to the next add(' at line start.
const sourceOf = id => {
  const start = source.indexOf(`add('${id}'`);
  assert.ok(start > -1, `No add() call for "${id}"`);
  const next = source.indexOf("\nadd('", start + 1);
  return source.slice(start, next === -1 ? source.length : next);
};

// Note 82 — a customer may have several bikes, so the record needs a bike chooser.
{
  const body = sourceOf('customer-record');
  assert.match(body, /<select/, 'customer-record has no <select> for choosing a bike');
  assert.match(body, /bike/i, 'customer-record bike chooser is not identifiable as a bike chooser');
}

console.log('check-notes: all applied-note assertions passed');
```
