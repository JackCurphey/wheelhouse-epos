### 11 Nov 2026: Quick buttons on the server (`openspec/changes/owner-setup-till-payments-eod` group 1, `set-till-quick`, `set-till-quick-add`)

Decided here, for Jack to overrule.

1. **A button whose item is off sale stays, marked "Not on sale".** The
   server sends `onSale: false` for it; the till will hide it and the Settings
   row will say "Not on sale". Checked: `setup.mjs` draws no off-sale button,
   and design.md section 5 point 4 says "'Not on sale' on its Settings row,
   hidden on the till". No built screen marks an off-sale item this way (the
   services list hides inactive services), so this is new.
2. **Name limits: a group up to 20 characters, a button's label up to 40.**
   An empty label shows the item's own name. Checked: no limit is drawn, and
   design.md section 5 point 5 sets them. Chosen to fit: a group is a pill,
   and a button is a tile. *Pattern:* the nearest built limit is a booking
   slot's name, 40 characters (`server/routes/workshop-settings.js`).
3. **A button stays when its product or service is deleted, marked "Not on
   sale".** Deleting either in the app only turns it off, so the button
   follows point 1. Only if the row itself is removed (today, when a whole
   shop is removed) do its buttons go with it. Not drawn, and no decision
   covers it. *Pattern:* a product's price history (migration 122) and a
   service's included services (migration 031) go with a removed row the
   same way.

### 12 Nov 2026: The website model (`openspec/changes/website-management` group 1, `ws-page`, `ws-page-changes`, `ws-discard`, `ws-history`)

Decided here, for Jack to overrule. History keeping 90 days is in
`../2026-11-12-website-defaults-taken.md`, not here.

1. **Old History rows are cleared when the website is changed or History is
   opened, not on a timer.** Checked: design.md section 1 says only that History
   keeps 90 days; the build has no nightly job runner for shop data. The row
   customers see now is never cleared, however old. *Pattern:* none built;
   the nearest is the quote expiry, worked out when a quote is read.
2. **A shop whose old customer site is already on starts with its website
   published and on.** Checked: design.md section 1 says the row is seeded from
   `storefront_settings`, and says nothing of a site that is already live.
   Starting it off would take a live site down the first time an Owner opens
   the Website page. Its first History row is marked "First published".
3. **The headline starts as the shop's name.** Checked: `website.mjs` draws the
   Home page headline as "[Headline]", and `storefront_settings` has no
   headline. The shop's name is real data, so nothing is invented.
4. **Before the first publish, no changes are listed.** Checked: `ws-page`
   (website off, never published) draws no "[n] unpublished changes" line; it
   draws "Turn it on", which publishes everything.
5. **Logo and colour show in the changes list as "Every page"; tracking tools
   as "Tracking tools".** Checked: `ws-page-changes` names pages ("Home page",
   "Collection and returns") but draws no logo, colour or tracking change.
6. **Publish or Discard with nothing to publish or discard is refused.** The
   screen hides both buttons then (`ws-page-on`); the server refuses too, so
   History never gets an empty version.
7. **Someone who isn't an Owner opening the Website page gets the Owners'
   names with the refusal.** Checked: `ws-no-access` draws "People with “Can
   edit the website” can change it: Jack Lewis. Ask them if something needs
   changing." Until roles (WP-1.1), the people who can are the Owners.
   *Pattern:* `ownerOnly` refusals elsewhere give only a sentence.
8. **A new photo clears its description and its "only decoration" tick.** The
   old description was written for the old photo, so it is counted again as
   needing one. Not drawn.
9. **Once the website has been opened, only the Website page turns the
   customer site on or off.** The old Settings route that switched
   `storefront_settings.enabled` no longer reopens a site an Owner turned off.
   Checked: design.md says "keep `storefront_settings.enabled` in step with
   `is_on`"; the Website page keeps it in step, and nothing else should win.
10. **A shop whose old customer site is already on counts as set up, with
    Wheelhouse's own website.** Checked: design.md section 1 says `kind` is
    "NULL until the three-step start picks one"; a shop already selling on the
    old site has in effect picked it, and sending it through "Step 1 of 3"
    would offer to swap it for Shopify while it is live.
11. **The starting wording for Collection and returns and for Privacy is
    headings with bracketed gaps**, such as "[How long customers have to
    collect]". Jack's default 1 (`docs/decisions/2026-11-12-website-defaults-taken.md`)
    says "headings and bracketed gaps"; the headings themselves are not drawn
    (`website.mjs` line 88 lists only the page names).
12. **History names the pages that changed, and the part itself for one on
    every page.** Checked: `website.mjs` line 369 draws "Home page, Theme
    colour". The colour is called "Main colour", as the start and the editor
    draw it (lines 165 and 359), not "Theme colour".
13. **Once the Website page is in use, the old Settings route and the old logo
    and big photo uploads are refused** ("The website is now changed on the
    Website page."). Their edits went to the old settings, which the next
    publish overwrote, so a change there was silently lost. The old panel is
    removed in pull request 2.
14. **A site that was already live on the old website has no name on its
    first publish.** Nobody pressed Publish, so "Last published by" and its
    first History row ("First published") carry no name until someone
    publishes. Checked: `ws-page` draws "Last published by Jack Lewis on
    [date]" and says nothing of a site that was published for the shop.
15. **The product counts:** "go online" counts products shown on the website
    that have a price; "have no photo" counts those among them; "have no price"
    counts products shown on the website at £0. Checked: `website.mjs` COUNTS
    draws "[n] have no price (stay off until priced)", so an unpriced product
    is not one that goes online.
16. **The old Settings route still sets the theme once the Website page is in
    use**, and refuses everything else (decision 13). The Website page has no
    theme of its own until the main colour in pull request 3, and nothing else
    could change it.
17. **A page with one part lists its change by the page name alone.** Checked:
    `website.mjs` CHANGES draws "Collection and returns — Returns text"; the
    server keeps part names, not a description of the edit, so "Collection and
    returns — Collection and returns" would repeat itself. The screen shows the
    page name (pull request 2).
