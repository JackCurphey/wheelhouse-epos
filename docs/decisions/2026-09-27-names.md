# Names: one word for each thing

Date: 27 September 2026. **Status:** items 1-4 decided by Jack; items 5-8 are
defaults chosen by Claude, **Jack to confirm**.

The project had grown several names for the same thing: the product was
"Wheelhouse", "Wheelhouse EPOS", "Bike Shop EPOS" and "Wheelhouse Workshop";
the selling screen was "Front Desk"; the Release 1 design collection was the
"atlas". This record is the glossary. Anything people see - screens, messages,
page titles, docs - uses the name in the left column. Code identifiers,
database names and addresses that still use an old name are listed at the end,
with the reason each was left.

### How the renames were applied

- **Screen designs.** Files renamed: `Wheelhouse-Release-1-Journey-Atlas.html`
  → `Wheelhouse-Release-1-Screen-Designs.html`, `atlas.js` → `designs.js`,
  `atlas.css` → `designs.css`, and
  `docs/superpowers/plans/2026-09-20-phase-0-atlas-revision.md` →
  `2026-09-20-phase-0-screen-designs-revision.md`. Placeholders
  `__ATLAS_CSS__`/`__ATLAS_JS__` → `__DESIGNS_CSS__`/`__DESIGNS_JS__`; the
  checks' page address `https://atlas.example/` →
  `https://screen-designs.example/`; `evidence/atlas-overview.png` →
  `evidence/screen-designs-overview.png`; `ATLAS_IDS` → `SCREEN_DESIGN_IDS`.
  The HTML, `screen-index.json` and `evidence/render-input.json` were
  regenerated by `package.py`, `check-static.mjs` and `export-screens.mjs`,
  not edited by hand. The CI steps were renamed to match.
- **Roles in the screen designs.** Every screen labelled "Service desk ·
  desktop" is now "Staff · desktop".
- **Customer portal.** Where "customer portal" meant the older
  sign-in-and-see-my-bookings pages in `public-portal/` (not the booking link),
  it now reads "customer booking pages" or "online booking pages", because
  those pages are not one booking's link.

## Known internal names that still differ

These keep an old name on purpose. Renaming them would change the database, an
address other code or a deployed shop depends on, or a third party's own name.
Whether to rename any of them is a separate decision.

**Database (columns, tables, migrations)** - left because renaming needs a
migration and every deployed database would have to follow:

- `employees.is_cashier` (means "is Staff") and `employees.is_mechanic`;
  `logins.is_owner` already matches the Owner role
- `sales.cashier_id`, `sale_documents.cashier_id` (the Staff member who took
  the sale)
- table `storefront_settings` and its policy `storefront_settings_shop_isolation`
  (the Website settings); migration file `server/migrations/010_storefront.sql`
- `shopify_connections.storefront_api_token` (Shopify's own "Storefront API"
  token - see Third-party names)
- `products.shopify_inventory_item_id` (Shopify's own "inventory item")
- the `epos` database and the `epos_app` role

**API routes, query values and response fields** - left because the screens,
the tests and any bookmarked address use them:

- `GET /api/employees?role=cashier` (returns Staff)
- request/response fields `cashierId`, `cashierName`, `isCashier`
- `/api/storefront/info`, `/api/storefront/products`,
  `/api/storefront-settings`, `/api/storefront-settings/logo`,
  `/api/storefront-settings/hero`, and the `?storefrontSlug=` query value
- `/api/portal/*` (the online booking pages and the booking link), including
  `/api/portal/:shopSlug/booking-links/:code` and its `/cancel`, `/change`
  and `/withdraw-change`
- the website address forms `/store/<slug>` and `<slug>.wheelhouseepos.com`,
  and the `STOREFRONT_BASE_DOMAIN` environment variable

**Folders and files** - left because the server, the build and the tests load
them by path:

- `public-storefront/` (with `storefront.js`, `storefront.css`),
  `server/storefront.js`, `tests/storefront-public.test.js`,
  `tests/storefront-settings.test.js`, `tests/storefront-shopify-cart.test.js`
- `public-portal/` (with `portal.js`, `portal.css`), `tests/helpers/portal.js`,
  `server/booking-link.js`, `tests/workshop-portal.test.js` and the
  `tests/portal-*.test.js` files
- the historical docs `docs/superpowers/specs/2026-08-30-shop-storefronts-design.md`
  and `docs/superpowers/plans/done/2026-08-30-storefront-framework.md` (other
  docs link to them by name; their text now says "website")
- `start-epos.vbs`, the repository name `wheelhouse-epos`, and the
  `package.json` name `bike-shop-epos` (see below)

**Code identifiers in the staff app (`public/app.js`, `public/styles.css`)** -
left because they are not shown to anyone and renaming them is churn with a
risk of breaking a selector:

- route ids and addresses: `till` (the Till tab, `#till`), `inventory`
  (`#office/inventory`, the Stock tab), `front-desk`
  (`#office/edit-shop/front-desk`, "Edit Shop > Till")
- functions and variables: `renderInventory`, `inventorySelectedIds`,
  `renderEditFrontDesk`, `activeCashiers`, `activeCashierId`,
  `loadActiveCashiers`, `renderCashierPills`, `salesCashierFilter`,
  `resolveCashierId` (server)
- element ids and classes: `back-to-stockroom`, `data-action="frontdesk"`,
  `cashier-pills`, `data-cashier`, `sales-cashier-filter`, `team-is-cashier`,
  `.cashier-select-row`, `.cashier-select-label`, `.badge.role-cashier`,
  every `storefront-*` id in the Website settings panel
- the planned WorkOS role key `cashier` in
  `docs/superpowers/specs/2026-08-31-workos-auth-migration-design.md` and its
  plan (a role key, not a label; the label there is "Till staff")

**Screen design ids** - left because the React screens and routes are keyed by
them: `progress` ("Return to the booking link"), `expired`, `desk`,
`pos`, `pos-done`.

**Third-party names** - these are other companies' names for their own
features and stay as they are: Shopify's "Storefront API" (and the
`X-Shopify-Storefront-Access-Token` header), Shopify "inventory", and
Lightspeed's "work order".

**The `package.json` name.** It stays `bike-shop-epos`. The package is not
published and nothing in the repository refers to the name, but regenerating
`package-lock.json` with `npm install --package-lock-only` did more than
rename it: it also added six new bundled entries under
`@tailwindcss/oxide-wasm32-wasi`. The rule was to rename only if the lockfile
changed in name alone, so it was left. The `description` now starts with
"Wheelhouse".

## Left as they were, on purpose

- **The sample printer name "Front desk Zebra"** in the screen designs and
  `tests/workshop-schema.test.js`. It is a printer named after where it
  stands, not the Till screen.
- **`prototype/`** - the separate interactive workshop simulation. It still
  says "progress link", and its browser tests find buttons by that text.
- **Binary files** - the review PDFs, the review ZIP and the PNGs in
  `docs/design/release-1-journey/` were rendered from older text and still
  contain old names. They are not regenerated here.
- **"booking portal"** (the online booking pages as a whole) is not on the
  list above, so it was not renamed.
- **Quoted speech** in decision records and reviews keeps the words that were
  said.
